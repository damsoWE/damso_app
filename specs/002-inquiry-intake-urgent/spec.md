## Clarifications

### Session 2026-10-26

- Q: 기기 알림(푸시)을 이번 F2 범위에서 만드나? → A: 만든다. 팀이 외부 알림 서비스 프로젝트(Firebase)를 이미 만들었다. F2에서는 교사 기기 등록·해제와 알림 수신·이동까지 만들고, 학부모 기기의 답변 도착 알림은 F4에서 다룬다.
- Q: 로그인 후 화면 이동을 IA처럼 하단 탭(홈·문의·마이페이지)으로 바꾸나? → A: 바꾼다. Figma 기준으로 학부모·교사에 하단 탭 3개를 지금 도입하고, 탭마다 이동 기록을 따로 유지한다. 슈퍼 관리자는 이번에 그대로 둔다.
- Q: 교사 문의 목록과 홈은 언제 새 문의를 다시 불러오나? → A: 화면을 열 때·당겨서 새로 고칠 때에 더해, 앱이 열려 있을 때 문의 알림을 받으면, 그리고 앱이 백그라운드에서 다시 앞으로 올 때 자동으로 다시 불러온다. 일정 간격의 자동 조회는 하지 않는다.
- Q: 긴급 전달 안내의 109·112 번호를 누르면 바로 전화 걸기 화면이 열리나? → A: 연다. 번호를 버튼으로 보여 주고, 누르면 기기의 전화 걸기 화면을 번호가 입력된 상태로 연다. 통화 버튼은 학부모가 직접 누른다(앱이 바로 전화를 걸지 않는다).
- (plan 반영, 백엔드 원본 명세 0.5.0) 보내기 결과의 안내는 서버가 **코드**로 준다: 안내 코드(접수·긴급 전달·응답 가능 시간 안내)와 번호 코드 목록(109·112). 위기 종류별 번호는 서버가 골라 주고, 앱은 코드를 고정 문구로 바꿔 보여 준다. 학부모 문의 목록에는 제목이 없고, 교사 문의 목록은 나눠서(한 번에 20건) 불러온다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 학부모가 자녀를 고르고 문의를 보낸다 (Priority: P1)

학부모가 홈(F2-1)에서 자녀를 고른 상태로 "문의 작성"을 누르면 문의 작성(F2-2)이 열린다. 어느 자녀에 대한 문의인지 보이고, 제목 없이 하고 싶은 말을 자유롭게 쓴다. 보내면 문의 접수(F2-5) 안내가 보인다. 보낸 문의는 고치거나 지울 수 없다.

**Why this priority**: 문의가 접수되지 않으면 긴급 전달·처리 단계·답변이 모두 시작되지 못한다. 학부모의 문의권을 막지 않는 것이 이 기능의 출발점이다.

**Independent Test**: mock 실행에서 학부모로 로그인해 자녀를 고르고 문의를 보낸 뒤, 접수 안내가 보이고 문의 목록에 새 문의가 생기는지, 그 문의를 고치거나 지우는 버튼이 어디에도 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 자녀가 연결되고 담임이 있는 학부모, **When** 문의 작성에서 본문을 입력하고 보냄, **Then** 문의 접수(F2-5) 안내가 시스템 안내로 보이고 나의 문의 목록에 새 문의가 생긴다.
2. **Given** 본문이 비어 있거나 공백뿐, **When** 문의 작성 화면, **Then** 보내기 버튼이 비활성이다.
3. **Given** 본문 입력 중, **When** 글자를 입력함, **Then** 현재 글자 수와 상한(2,000자)이 보이고, 2,000자를 넘기면 보내기 버튼이 비활성이며 상한 안내가 보인다.
4. **Given** 자녀가 둘인 학부모, **When** 홈에서 둘째 자녀를 고르고 문의 작성, **Then** 작성 화면에 둘째 자녀가 대상으로 보이고 문의는 둘째 자녀의 담임에게 간다.
5. **Given** 담임이 아직 없는 자녀가 선택됨, **When** 문의 작성을 열려고 함, **Then** 작성 화면이 열리지 않고 "담임 선생님이 연결된 뒤 문의할 수 있다"는 안내가 보인다. 작성 중에 서버가 같은 사유로 거부하면 서버 안내가 보이고 작성 화면에 머물며 쓴 내용은 남는다.
6. **Given** 보내는 중, **When** 보내기 버튼을 여러 번 누르거나 네트워크가 끊겨 다시 보냄, **Then** 문의는 한 건만 접수된다.
7. **Given** 1분 안에 이미 문의를 보낸 학부모, **When** 일반 문의를 또 보냄, **Then** 서버 안내와 다시 보낼 수 있을 때까지 남은 시간이 1초 단위로 줄어들며 보이고, 쓴 내용은 그대로 남는다. 버튼은 막지 않아 긴급 문의는 바로 보낼 수 있다.
8. **Given** 보내기가 실패함(네트워크·서버 오류), **When** 실패 안내가 보임, **Then** 쓴 내용은 그대로 남아 다시 보낼 수 있다.
9. **Given** 본문을 쓰다가, **When** 보내지 않고 화면을 떠나려 함, **Then** 작성한 내용이 사라진다는 확인을 받는다.

### User Story 2 - 긴급 문의는 "바로 전달했어요" 안내와 위기 종류에 맞는 번호를 보여 준다 (Priority: P1)

학생 안전·학대·자해와 관련된 문의를 보내면 서버가 긴급으로 판정해 담임에게 바로 전달한다. 학부모에게는 일반 접수 안내 대신 긴급 전달 안내(F2-3 계열)가 보인다. "선생님께 바로 전달했어요"와 함께 위기 종류에 맞는 외부 상담·신고 번호만 고정 문구로 보이고, 종류를 알 수 없으면 기본 안내(112·109 함께)가 보인다.

**Why this priority**: 안전 사안을 보낸 학부모에게 전달 사실과 도움받을 곳을 즉시 알려야 한다. 안내가 늦거나 틀리면 학부모가 위기 상황에서 헤맨다(원칙 IV).

**Independent Test**: mock 실행에서 긴급 판정 사례(위기 종류 3가지 + 분류 안 됨)를 각각 보내고, 안내 화면과 보이는 번호가 종류에 맞는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 서버가 긴급으로 판정, **When** 보내기가 끝남, **Then** 긴급 전달 안내가 보이고 "선생님께 바로 전달했어요"가 시스템 안내로 보인다.
2. **Given** 위기 종류가 자해, **When** 긴급 전달 안내, **Then** 자살예방 상담전화 109만 보인다(F2-3c).
3. **Given** 위기 종류가 학대, **When** 긴급 전달 안내, **Then** 아동학대 신고 112만 보인다(F2-3d).
4. **Given** 위기 종류가 그 밖의 안전, **When** 긴급 전달 안내, **Then** 번호 없이 전달 안내만 보인다(F2-3).
5. **Given** 위기 종류를 분류하지 못함(서버가 112·109를 함께 줌) 또는 서버가 준 번호가 모두 앱이 모르는 값, **When** 긴급 전달 안내, **Then** 기본 안내(112·109 함께)가 바로 보인다(F2-3b). 화면은 분류 결과를 기다리지 않는다.
6. **Given** 1분 안에 이미 문의를 보낸 학부모, **When** 긴급으로 판정되는 문의를 보냄, **Then** 제한 없이 접수되어 긴급 전달 안내가 보인다.
7. **Given** 109 또는 112가 보이는 긴급 전달 안내, **When** 번호 버튼을 누름, **Then** 기기의 전화 걸기 화면이 그 번호가 입력된 상태로 열리고, 통화는 학부모가 직접 누를 때만 걸린다.
8. **Given** 긴급 전달 안내, **When** 화면의 문구를 점검, **Then** 모두 앱에 정해 둔 고정 문구이고 교사의 판단이나 약속처럼 보이는 문구가 없다.

### User Story 3 - 교사가 문의 목록에서 긴급을 먼저 알아보고 원문을 확인한다 (Priority: P1)

교사가 홈(F3-4)이나 문의 목록(F3-1)을 열면 담당 학급의 문의가 보이고, 긴급 문의가 일반 문의와 구분되어 맨 위에 보인다. 긴급 문의를 누르면 긴급 문의 상세(F3-5)에서 원문을 그대로 본다. 처음 열어 본 순간 학부모 쪽 처리 단계가 "교사 확인"으로 바뀐다.

**Why this priority**: 교사가 긴급 문의를 알아보고 내용을 볼 수 있어야 즉시 전달이 의미가 있다.

**Independent Test**: mock 실행에서 교사로 로그인해 일반·긴급이 섞인 목록의 구분·정렬을 확인하고, 긴급 문의를 연 뒤 같은 문의가 학부모 쪽에서 "교사 확인" 단계로 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 담당 학급에 일반·긴급 문의가 섞여 있음, **When** 교사가 문의 목록을 엶, **Then** 긴급 문의가 긴급 표시와 함께 맨 위에 보이고, 각 문의는 학생 이름·제목·접수 시각·처리 단계로 구분된다.
2. **Given** 교사 홈, **When** 확인하지 않은 긴급 문의가 있음, **Then** 홈 상단에 긴급 카드가 보이고 누르면 긴급 문의 상세로 간다.
3. **Given** 긴급 문의, **When** 교사가 상세를 엶, **Then** 원문이 그대로(정리본 없이) 보이고, "원문 열람이 기록된다"는 안내가 보인다.
4. **Given** 문의 목록과 상세, **When** 화면의 모든 글자를 점검, **Then** 학부모의 이메일·연락처는 없다.
5. **Given** 담당 학급의 문의가 없음, **When** 문의 목록, **Then** 빈 상태 안내가 보인다.
6. **Given** 다른 학급의 문의 주소로 직접 이동, **When** 서버가 거부, **Then** 서버 안내가 보이고 내용은 보이지 않는다.

### User Story 4 - 학부모가 보낸 문의의 처리 단계를 확인한다 (Priority: P2)

학부모가 나의 문의 목록(F2-4)이나 홈의 문의 영역(F2-1)에서 보낸 문의를 본다. 카드를 펼치면 처리 단계가 시각과 함께 시간순으로 보인다. 일반 문의는 접수 → 정제 → 교사 확인 → 답변 완료, 긴급 문의는 접수 → 교사에게 전달됨 → 교사 확인 → 답변 완료로 진행한다.

**Why this priority**: 문의가 어디까지 갔는지 알아야 불안과 재문의가 줄지만, 보내기와 긴급 전달이 먼저다.

**Independent Test**: mock 실행에서 일반·긴급 문의를 하나씩 보낸 뒤 목록 카드를 펼쳐 단계와 시각을 확인하고, 정제 중 → 완료로 바뀌는 mock 문의의 단계가 다시 불러올 때 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 보낸 문의가 있음, **When** 나의 문의 목록, **Then** 최근 문의가 위에 보이고 각 카드에 대상 자녀·긴급 여부·접수 시각·현재 단계가 보인다.
2. **Given** 일반 문의 카드, **When** 펼침, **Then** 지나온 단계가 시각과 함께 시간순으로 보인다.
3. **Given** 긴급 문의 카드, **When** 펼침, **Then** "접수"와 "교사에게 전달됨"이 시각과 함께 보이고, 교사가 확인한 뒤에는 "교사 확인"도 보인다.
4. **Given** 문의 카드, **When** 목록, **Then** 긴급 문의는 "긴급 문의" 표시가 보이고, 일반 문의는 긴급 표시 없이 단계만 보인다(학부모 목록에는 서버 제목이 없다).
5. **Given** 긴급 문의 카드, **When** 누름, **Then** 그 문의의 긴급 전달 안내(US2와 같은 규칙)를 다시 본다.
6. **Given** 보낸 문의가 없음, **When** 나의 문의 목록·홈, **Then** 빈 상태(F2-1b) 안내와 "문의 작성" 버튼이 보인다.
7. **Given** 목록을 불러오지 못함, **When** 오류, **Then** 서버 안내와 다시 시도 버튼이 보인다.

### User Story 5 - 응답 가능 시간 밖에 보낸 일반 문의는 "응답 가능 시간에 전달됩니다"를 보여 준다 (Priority: P2)

학부모는 언제든 문의를 보낼 수 있다. 교사의 응답 가능 시간 밖에 보낸 일반 문의는 접수되지만 교사 알림은 응답 가능 시간이 시작될 때로 미뤄진다. 이 경우 학부모에게는 일반 접수 안내 대신 전달 준비 지연(F2-5a) 안내가 보인다.

**Why this priority**: 교사의 사생활과 학부모의 문의권을 함께 지키는 안내지만, 문의 자체는 막지 않으므로 P1 뒤에 온다.

**Independent Test**: mock 실행에서 응답 가능 시간 밖으로 설정된 담임에게 일반 문의를 보내 F2-5a 안내가 보이는지, 긴급 문의는 같은 상황에서도 긴급 전달 안내가 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 서버가 "응답 가능 시간 밖이라 알림이 미뤄짐"으로 응답, **When** 일반 문의 보내기가 끝남, **Then** 전달 준비 지연 안내와 "선생님 응답 가능 시간에 전달됩니다"가 시스템 안내로 보인다.
2. **Given** 응답 가능 시간 안, **When** 일반 문의 보내기가 끝남, **Then** 일반 접수 안내(F2-5)가 보인다.
3. **Given** 응답 가능 시간 밖, **When** 긴급 문의 보내기가 끝남, **Then** 지연 안내가 아니라 긴급 전달 안내가 보인다.
4. **Given** 문의 작성 화면, **When** 발송 시각을 고르는 기능을 찾음, **Then** 그런 기능은 없다.

### User Story 6 - 교사가 응답 가능 시간과 일반 알림을 설정한다 (Priority: P2)

교사가 마이페이지에서 응답 가능 시간·알림 설정(F3-8)을 열어 요일별 시작·종료 시각과 일반 문의 알림 켜기/끄기를 저장한다. 긴급 알림은 끌 수 없다는 안내만 보이고 끄는 항목은 없다.

**Why this priority**: 응답 가능 시간 지연(US5)이 실제로 동작하려면 교사가 시간을 정할 수 있어야 한다. 설정이 없어도 접수와 긴급 전달은 동작하므로 P2다.

**Independent Test**: mock 실행에서 교사로 시간을 저장하고 다시 열어 저장값이 보이는지, 시작이 종료보다 늦으면 저장되지 않는지, 긴급 알림을 끄는 항목이 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 응답 가능 시간을 설정한 적 없는 교사, **When** 설정 화면을 엶, **Then** "설정하지 않으면 언제든 응답 가능으로 본다"는 안내가 보인다.
2. **Given** 교사, **When** 요일별 시작·종료 시각을 정해 저장, **Then** 저장 완료가 보이고 다시 열면 저장한 값이 보인다.
3. **Given** 시작 시각이 종료 시각보다 늦거나 같음, **When** 저장, **Then** 해당 요일에 안내가 보이고 저장되지 않는다.
4. **Given** 교사, **When** 일반 알림을 끔, **Then** 저장되고 "긴급 알림은 항상 받는다"는 안내가 함께 보인다.
5. **Given** 설정 화면, **When** 긴급 알림 항목을 찾음, **Then** 끌 수 있는 항목이 없다.
6. **Given** 학부모·슈퍼 관리자, **When** 이 화면 주소로 이동, **Then** 자기 역할 홈으로 보내진다.

---

### User Story 7 - 교사 기기로 문의 알림을 받는다 (Priority: P3)

교사가 앱에 로그인하면 이 기기가 알림 수신 기기로 등록되고, 긴급 문의와 (응답 가능 시간 안의) 일반 문의 알림을 받는다. 알림에는 이름·본문 없이 고정 문구만 보인다. 로그아웃하면 이 기기의 등록이 풀린다.

**Why this priority**: 긴급 즉시 알림이 교사에게 실제로 닿으려면 필요하지만, 알림이 없어도 교사 목록의 긴급 표시는 동작하므로 화면보다 뒤에 온다.

**Independent Test**: 교사로 로그인한 기기에서 긴급 문의 알림이 고정 문구로 오는지, 로그아웃 후에는 오지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 교사가 로그인한 기기, **When** 담당 학급에 긴급 문의가 접수됨, **Then** 고정 문구 알림이 오고 누르면 긴급 문의 상세로 간다.
2. **Given** 알림, **When** 기기 잠금 화면에 보임, **Then** 학생·학부모 이름과 본문이 없다.
3. **Given** 등록된 기기, **When** 로그아웃·탈퇴, **Then** 이 기기의 등록이 풀리고 알림이 오지 않는다.
4. **Given** 교사가 알림 권한을 거부함, **When** 앱 사용, **Then** 문의 목록·긴급 표시는 그대로 동작하고, 응답 가능 시간·알림 설정 화면에 "기기 알림이 꺼져 있다"는 안내와 기기 설정으로 가는 방법이 보인다.
5. **Given** 앱이 열려 있는 상태, **When** 긴급 알림이 옴, **Then** 화면 안에서도 알림이 보이고 누르면 긴급 문의 상세로 간다.
6. **Given** 학부모·슈퍼 관리자 계정, **When** 로그인, **Then** 이번 기능에서는 기기 등록을 하지 않는다(학부모는 F4).

---

### User Story 8 - 서버 없이 mock으로 문의의 모든 상태를 시연한다 (Priority: P2)

개발자와 기획자가 서버 없이 mock으로 실행해 일반 접수, 응답 가능 시간 밖 접수, 긴급 판정(위기 종류 3가지와 분류 안 됨), 1분 제한, 담임 없는 자녀, 정제 중 → 완료로 바뀌는 문의, "원문 확인 필요" 문의, 남의 문의 접근 거부(403), 접근 권한 만료 → 갱신을 모두 볼 수 있다.

**Why this priority**: F2 API 명세 태그가 아직 공개되지 않아, 화면은 mock으로 먼저 만들고 확인해야 한다. constitution이 요구하는 mock 케이스이기도 하다.

**Independent Test**: mock 실행에서 quickstart의 데모 입력표대로 각 상태를 재현한다.

**Acceptance Scenarios**:

1. **Given** mock 실행, **When** 정해 둔 데모 입력으로 문의를 보냄, **Then** 일반 접수·지연 접수·긴급(4가지)·1분 제한 상태를 각각 재현할 수 있다.
2. **Given** mock 실행, **When** 교사 문의 목록을 다시 불러옴, **Then** "정리 중"이던 데모 문의가 다음 조회에서 정리 완료로 바뀌어 보이고, "원문 확인 필요" 데모 문의가 있다. 학부모 목록에서는 같은 문의의 단계가 접수 → 정제로 바뀐다.
3. **Given** mock 실행, **When** 남의 문의를 여는 데모 동작, **Then** 403 서버 안내가 보인다.

---

### Edge Cases

- 본문 글자 수는 사람이 보는 글자 기준으로 센다. 이모지·줄바꿈이 있어도 서버와 같은 방식으로 2,000자를 센다.
- 보내는 도중 앱이 응답을 받지 못하면(시간 초과) 같은 작성 내용을 다시 보낼 때 같은 제출로 처리되게 해 두 건이 생기지 않게 한다. 같은 제출 표시로 내용이 다르다는 거부(409)를 받으면 서버 안내를 보이고 쓴 내용은 남긴다.
- 문의 작성 중 선택한 자녀의 연결이 풀리거나 담임이 해제되면, 보낼 때 서버 거부 안내를 보이고 쓴 내용은 남긴다.
- 작성 중인 본문은 화면이 열려 있는 동안 메모리에만 둔다. 기기에 임시 저장하지 않는다(원칙 III — 원문을 기기에 저장하지 않는다).
- 긴급 판정은 앱이 하지 않는다. 앱은 서버의 판정 결과만 보여 주고, 앱에서 긴급 표시를 바꾸는 기능은 없다.
- 긴급 전달 안내를 본 학부모가 앱을 닫았다 열어도, 나의 문의 목록의 그 문의에서 같은 안내를 다시 볼 수 있다.
- 위기 종류 결과가 나중에 바뀌어도(분류가 늦게 끝남) 다시 열 때 그 시점의 종류로 안내를 고른다. 이미 열려 있는 화면은 바꾸지 않는다.
- 응답 가능 시간은 한국 시간 기준이며 하루 안의 구간(시작 < 종료)이다. 자정을 넘기는 시간은 두 요일로 나눠 입력한다.
- 교사 문의 목록에는 학부모의 이름·이메일을 보이지 않는다. 학생 이름으로 구분한다.
- 문의·원문 화면은 화면 캡처·최근 앱 미리보기에서 내용이 보일 수 있다. 이를 막는 처리는 이번 범위가 아니다(Assumptions 참고).

## Requirements *(mandatory)*

### Functional Requirements

**문의 작성·보내기 (학부모)**

- **FR-001**: 학부모는 홈에서 고른 자녀를 대상으로 문의를 작성할 수 MUST 있다. 작성 화면에 대상 자녀(이름·학년·반)가 보인다. 대상 자녀를 바꾸려면 홈의 자녀 선택(F2-1a)을 쓴다.
- **FR-002**: 문의는 제목 없이 본문만 입력한다. 본문은 앞뒤 공백을 뺀 뒤 1자 이상 2,000자 이하일 때만 보낼 수 있고, 입력 중 현재 글자 수와 상한을 보여 준다.
- **FR-003**: 담임이 없는 자녀가 선택된 상태에서는 문의 작성을 시작할 수 없고, 그 사유를 앱 안내로 보인다. 작성 화면에서 보낼 때 서버가 같은 사유로 거부하면(그사이 담임이 해제된 경우) 서버 안내(`message`)를 보이고 작성 화면에 머물며 쓴 내용은 그대로 둔다(FR-006·FR-034와 같은 규칙).
- **FR-004**: 한 번의 작성 내용에 대한 보내기는 연타·재시도를 해도 한 건만 접수되어야 MUST 한다. 보내는 중에는 보내기 버튼을 다시 누를 수 없다.
- **FR-005**: 1분 제한(서버 시도 제한)에 걸리면 서버 안내와 남은 시간을 1초 단위로 줄여 보여 준다. 쓴 내용은 그대로 둔다. 남은 시간 동안에도 보내기 버튼은 막지 않는다 — 긴급 문의는 제한을 받지 않으므로(US2-6, 원칙 IV) 판단은 서버에 맡긴다(구현 중 결정 2026-10-26).
- **FR-006**: 보내기가 실패하면(네트워크·서버 오류·서버 거부) 서버 안내를 보이고 쓴 내용은 그대로 둔다.
- **FR-007**: 쓴 내용이 있는 상태로 작성 화면을 떠나면 내용이 사라진다는 확인을 받는다. 작성 중인 본문은 기기에 저장하지 MUST NOT 한다.
- **FR-008**: 보낸 문의를 수정·삭제하는 기능은 어디에도 두지 MUST NOT 한다. 발송 시각을 고르는 예약 기능도 두지 않는다.

**보낸 뒤 안내 (학부모)**

- **FR-009**: 보내기가 끝나면 서버 결과에 따라 세 가지 중 하나를 보여 준다. 일반 접수(F2-5), 응답 가능 시간 밖 일반 접수(F2-5a, "선생님 응답 가능 시간에 전달됩니다"), 긴급 전달(F2-3 계열, "선생님께 바로 전달했어요").
- **FR-010**: 긴급 전달 안내의 외부 번호는 서버가 위기 종류에 맞춰 준 번호 코드 목록을 앱의 고정 문구로 바꿔 보여 준다(자해 → 자살예방 상담전화 109, 학대 → 아동학대 신고 112, 그 밖의 안전 → 번호 없음, 분류 안 됨 → 112·109 함께). 앱이 모르는 코드는 버리고, 버린 뒤 남는 번호가 없는데 서버가 번호를 하나 이상 줬다면 기본 안내(112·109 함께)를 보여 준다. 안내 문구도 서버가 준 안내 코드를 앱의 고정 문구로 바꿔 보여 준다.
- **FR-010a**: 긴급 전달 안내의 외부 번호(109·112)는 누를 수 있는 버튼으로 보여 주고, 누르면 기기의 전화 걸기 화면을 그 번호가 입력된 상태로 연다. 앱이 직접 전화를 걸지 않는다. 전화 걸기 화면을 열 수 없는 기기(태블릿 등)에서는 번호를 글자로 보여 주고 버튼은 비활성으로 둔다.
- **FR-011**: 긴급 전달 안내는 위기 종류 결과를 기다리지 않고 보내기 결과를 받는 즉시 보여 준다.
- **FR-012**: 접수·지연·긴급 안내는 모두 앱에 정해 둔 고정 문구로만 구성하고, 교사 메시지와 시각적으로 구분되는 시스템 안내로 표시해야 MUST 한다. 서버나 AI가 만든 문장을 안내 문구로 쓰지 MUST NOT 한다(서버 오류 안내 `message`는 예외).
- **FR-013**: 안내 화면에서 "보낸 문의 보기"로 나의 문의 목록(F2-4)으로 간다. 뒤로 가기로 작성 화면에 돌아가 같은 내용을 다시 보내지 않게 한다.

**처리 단계 (학부모)**

- **FR-014**: 나의 문의 목록(F2-4)은 학부모 본인이 보낸 문의를 최근 순으로 보여 준다. 각 카드에 대상 자녀·접수 시각·현재 처리 단계·긴급 여부가 보인다.
- **FR-015**: 카드를 펼치면 처리 단계가 시각과 함께 시간순으로 보인다. 일반 문의는 접수 → 정제 → 교사 확인 → 답변 완료, 긴급 문의는 접수 → 교사에게 전달됨 → 교사 확인 → 답변 완료다. 아직 오지 않은 단계는 흐리게 보인다.
- **FR-016**: 학부모 카드에는 서버 제목이 없다. 긴급 문의는 "긴급 문의" 표시를 붙이고, 일반 문의는 단계로 구분한다. 교사 목록의 제목은 서버가 준 값(긴급 "긴급 문의", 정리 중 "정리 중", 정리 실패 "원문 확인 필요", 정리 완료 시 정리된 제목)을 그대로 보여 준다.
- **FR-017**: 학부모 홈(F2-1)의 문의 영역은 선택한 자녀의 최근 문의를 보여 주고, 문의가 없으면 빈 상태(F2-1b)와 "문의 작성" 버튼을 보여 준다.
- **FR-018**: 긴급 문의 카드를 누르면 그 문의의 긴급 전달 안내를 FR-010 규칙으로 다시 보여 준다. 일반 문의 카드의 상세(F4-1)는 F4 범위이며, 이 기능에서는 카드 펼치기까지만 한다.
- **FR-019**: 문의 목록은 화면을 열 때, 다른 탭에서 이 탭으로 돌아올 때, 당겨서 새로 고칠 때 다시 불러온다. 로딩·빈 목록·오류(다시 시도) 상태를 갖는다.

**문의 확인 (교사)**

- **FR-020**: 교사의 문의 목록(F3-1)은 담당 학급의 문의를 보여 주며, 긴급 문의를 긴급 표시와 함께 맨 위에, 나머지는 최근 순으로 보여 준다(순서는 서버가 정한다). 각 항목에 학생 이름·제목·접수 시각·처리 단계가 보인다. 목록은 나눠서 불러오고, 끝까지 내리면 다음 묶음을 이어서 불러온다.
- **FR-020a**: 교사 문의 목록과 교사 홈은 화면을 열 때, 다른 탭에서 그 탭으로 돌아올 때, 당겨서 새로 고칠 때 다시 불러오고, 앱이 열려 있는 동안 문의 알림을 받았을 때와 앱이 백그라운드에서 다시 앞으로 왔을 때도 자동으로 다시 불러온다. 일정 간격으로 계속 조회하지는 않는다. 다시 불러오는 동안에도 보던 목록은 그대로 보인다.
- **FR-021**: 교사 홈(F3-4)은 확인하지 않은 긴급 문의가 있으면 상단에 긴급 카드로 보여 주고, 최근 문의 몇 건과 "문의 목록 보기"를 보여 준다.
- **FR-022**: 긴급 문의 상세(F3-5)는 원문을 그대로 보여 주고 원문 열람이 기록된다는 안내를 함께 보여 준다. 처음 연 시점에 처리 단계가 "교사 확인"으로 바뀌는 것은 서버가 정한다.
- **FR-023**: 교사 화면 어디에도 학부모의 이름·이메일·연락처를 보여 주지 MUST NOT 한다. 문의는 학생 이름으로 구분한다.
- **FR-024**: 일반 문의의 정리본 상세(F3-2)·원문 확인 필요(F3-3)·원문 열람(F3-6)은 F3 범위다. 이 기능에서는 목록에서 해당 문의가 보이고, 누르면 "준비 중" 안내를 보여 준다. (F3에서 대체: specs/003 FR-001~002)
- **FR-025**: 문의 본문은 일반 텍스트로만 표시하고, 화면 밖(기기 저장소·로그·분석 이벤트)에 남기지 MUST NOT 한다.

**응답 가능 시간·알림 설정 (교사)**

- **FR-026**: 교사는 응답 가능 시간·알림 설정(F3-8)에서 요일별로 응답 가능 여부와 시작·종료 시각을 정하고, 일반 문의 알림을 켜고 끌 수 MUST 있다.
- **FR-027**: 시작 시각은 종료 시각보다 빨라야 한다. 맞지 않으면 그 요일에 안내를 보이고 저장하지 않는다. 서버가 거부하면 서버 안내를 보인다.
- **FR-028**: 긴급 알림을 끄는 항목은 두지 MUST NOT 한다. "긴급 알림은 항상 받는다"는 안내만 보인다.
- **FR-029**: 응답 가능 시간을 설정하지 않은 교사에게는 "설정하지 않으면 언제든 응답 가능으로 본다"는 안내를 보인다.
- **FR-030**: 이 설정 화면은 교사만 들어갈 수 있다. 다른 역할이 주소로 들어오면 자기 역할 홈으로 보낸다.

**알림 수신 기기 (교사)**

- **FR-031**: 교사가 로그인하면(세션 복구 포함) 이 기기를 알림 수신 기기로 등록하고, 로그아웃·탈퇴 때 등록을 푼다. 등록 해제가 실패해도 로그아웃은 막지 않는다. 기기 식별 값이 바뀌면 다시 등록한다.
- **FR-031a**: 알림 권한은 교사에게만, 교사 홈에 들어왔을 때 기기에서 아직 허용·거부를 정하지 않은 경우에만 요청한다(이미 정했으면 다시 묻지 않는다. 앱은 요청 여부를 따로 저장하지 않고 기기의 권한 상태로 판단한다). 거부해도 앱 사용을 막지 않고, 설정 화면(F3-8)에 알림이 꺼져 있다는 안내를 보인다.
- **FR-031b**: 알림을 누르면(앱이 꺼져 있었어도) 해당 문의 화면으로 간다. 긴급은 긴급 문의 상세(F3-5), 일반·묶음 알림은 문의 목록(F3-1)이다. 로그인이 풀려 있으면 로그인 뒤 그 화면으로 간다.
- **FR-031c**: 알림 내용은 서버가 정한 고정 문구만 보여 주고, 앱이 알림 내용을 기기에 저장하거나 로그로 남기지 MUST NOT 한다.

**공통**

- **FR-032**: 기존 임시 문의 목록 화면(`/inquiries`)은 역할별 문의 화면(학부모 F2-4, 교사 F3-1)으로 대체한다.
- **FR-033**: mock 구현은 일반 접수, 응답 가능 시간 밖 접수, 긴급(자해·학대·그 밖의 안전·분류 안 됨), 1분 제한(남은 시간 포함), 담임 없는 자녀, 정제 중 → 완료 전이, "원문 확인 필요", 남의 문의 접근 403, 접근 권한 만료 → 갱신 → 재시도를 재현해야 MUST 한다.
- **FR-034**: 서버 오류는 F1과 같은 규칙으로 보여 준다(서버 안내 `message`만, 입력 오류는 해당 입력란 아래, 네트워크 오류는 일반 안내).
- **FR-035**: 학부모·교사는 로그인 후 하단 탭 3개(홈 · 문의 · 마이페이지)로 이동한다. 학부모는 F2-1 · F2-4 · F2-7, 교사는 F3-4 · F3-1 · F3-7이다. 탭마다 이동 기록을 따로 유지해, 다른 탭에 다녀와도 보던 화면이 남는다. 문의 작성·안내·상세·설정처럼 탭 안에서 연 화면은 탭 위에 쌓이고, 탭 모양과 아이콘은 Figma를 따른다. 슈퍼 관리자 화면은 이번에 바꾸지 않는다.

### Key Entities *(include if feature involves data)*

- **문의 (화면 표시용)**: 문의 ID, 대상 자녀(ID·이름), 긴급 여부, 접수 시각, 현재 처리 단계. 교사 화면에는 서버가 정한 제목과 정리 상태(정리 중·정리 완료·원문 확인 필요, 긴급은 없음)가 더 있다. 교사 화면에는 작성 학부모 정보가 없다.
- **처리 단계 이력**: 단계(접수·교사에게 전달됨·정제·교사 확인·답변 완료)와 시각의 시간순 목록. 앱은 보여 주기만 하고 바꾸지 않는다.
- **보내기 결과**: 접수된 문의 ID, 결과 종류(일반 접수·응답 가능 시간 밖 접수·긴급 전달), 긴급이면 위기 종류. 안내 화면을 고르는 기준이다.
- **작성 중인 문의**: 대상 자녀, 본문, 한 번의 작성에 하나씩 정하는 제출 표시(재시도 때 같은 값). 화면이 열려 있는 동안 메모리에만 있다.
- **응답 가능 시간 설정**: 요일별 응답 가능 여부·시작·종료 시각, 일반 알림 켜기/끄기. 긴급 알림은 항목이 없다.
- **알림 수신 기기**: 이 기기의 알림 식별 값과 등록 상태. 교사가 로그인한 동안만 등록되어 있다.
- **고정 안내 문구**: 접수·지연·긴급 전달·위기 종류별 번호 안내. 앱에 정해 둔 문구이며 서버나 AI가 만들지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 학부모가 홈에서 "문의 작성"을 누른 뒤 접수 안내를 보기까지, 글 쓰는 시간을 빼고 30초 안에 끝낼 수 있다.
- **SC-002**: 긴급으로 판정된 문의는 보내기 결과를 받은 즉시(위기 종류 결과를 기다리지 않고) 긴급 전달 안내가 보이는 비율이 100%다.
- **SC-003**: 위기 종류 4가지 경우(자해·학대·그 밖의 안전·분류 안 됨)에서 보이는 외부 번호가 규칙과 100% 일치한다.
- **SC-004**: 연타·재시도로 같은 작성 내용이 두 건 이상 접수되는 경우가 0건이다.
- **SC-005**: 보낸 문의를 수정·삭제하는 화면 요소가 0개다. 긴급 알림을 끄는 화면 요소가 0개다.
- **SC-006**: 학부모에게 보이는 접수·지연·긴급 안내는 100% 앱에 정해 둔 고정 문구다.
- **SC-007**: 교사 화면 어디에서도 학부모의 이름·이메일·연락처가 보이지 않는다(0건).
- **SC-008**: 교사 문의 목록에서 긴급 문의가 일반 문의보다 아래에 보이는 경우가 0건이다.
- **SC-009**: 문의 본문이 기기 저장소·로그·분석 이벤트에서 발견되는 경우가 0건이다.
- **SC-010**: 보내기에 실패하거나 1분 제한에 걸렸을 때 학부모가 쓴 내용을 잃는 경우가 0건이다.
- **SC-011**: mock 실행만으로 US8의 모든 상태를 서버 없이 재현할 수 있다.
- **SC-011a**: 앱이 열려 있는 교사 기기에 긴급 문의 알림이 오면, 별도 동작 없이 3초 안에 교사 홈의 긴급 카드와 문의 목록 맨 위에 그 문의가 보인다.
- **SC-012**: 교사가 로그아웃한 기기로 알림이 오는 경우가 0건이다.
- **SC-013**: 긴급 알림을 누른 교사가 두 번 이하의 동작(알림 누르기, 필요하면 로그인)으로 그 긴급 문의 상세를 보는 비율이 100%다.

## Assumptions

- 로그인·학부모–학생–담임 연결·학부모 홈의 자녀 선택(F2-1a)·교사 홈의 진입 화면은 F1을 그대로 쓰고, 이 기능에서 문의 영역을 채운다.
- 긴급 판정·1분 제한·같은 제출 판단·처리 단계 전이·원문 열람 기록은 모두 서버가 한다. 앱은 결과를 보여 주기만 하고 판정 규칙을 갖지 않는다.
- 위기 종류 분류는 백엔드 F3에서 채운다. 그전까지 서버는 위기 종류를 "분류 안 됨"으로 주므로 실서버에서는 기본 안내(112·109)만 보인다. 앱의 종류별 안내 규칙은 이 기능에서 완성하고 mock으로 확인한다.
- 일반 문의의 정리본 상세(F3-2)·원문 확인 필요(F3-3·F3-3a)·원문 열람(F3-6)은 F3, 학부모 문의 상세 스레드(F4-1·F4-1a·F4-1b)와 답변은 F4 범위다.
- 알림 목록(학부모 F2-6, 교사 F3-11)과 학부모 알림 설정(F2-8)은 이번 범위가 아니다. 백엔드 F2에 알림 목록 기능이 없고, 학부모의 답변 도착 알림 설정은 백엔드에서 F4로 정했다. 해당 진입점(🔔)은 이번에 두지 않는다.
- 응답 가능 시간 밖 여부는 보내기 결과로 서버가 알려 준다고 가정한다. 서버가 알려 주지 않으면 plan 단계에서 API 명세를 보고 정한다.
- API 명세 태그(`api-v0.5`)가 공개되면 `/fetch-api`로 받아 화면이 쓰는 필드를 맞춘다. 그전까지 데이터 모양은 백엔드 spec의 Key Entities를 기준으로 mock을 만든다.
- 기기 알림에는 팀이 만든 외부 알림 서비스(Firebase) 프로젝트를 쓴다. 연결 설정 파일을 저장소에 둘지, 빌드 때 주입할지는 constitution 원칙 VIII(시크릿을 앱·에셋에 넣지 않음)과 비밀값 검사(Gitleaks)를 기준으로 plan에서 정한다.
- 알림을 보내는 쪽(서버)과 묶음·재알림 규칙은 백엔드가 맡는다. 앱은 기기 등록·해제, 권한 요청, 알림 수신과 화면 이동만 한다.
- 화면 캡처 방지·최근 앱 미리보기 가리기는 이번 범위가 아니며 필요하면 별도 이슈로 다룬다.
- 문의 본문의 맞춤법 검사·자동 완성·키보드 학습은 기기 기본 동작을 따르되, 입력란 설정은 plan에서 검토한다.
