# Quickstart: 배포 서버 실연동 검증

배포 서버(`https://damso.jibang.site`)에서 F1~F3 화면이 끝까지 도는지 확인하는 순서. 결과는 `verification.md`에 시나리오 ID별로 적는다([data-model §2](./data-model.md#2-검증-기록-verificationmd)).

## 준비 (약 10분)

1. 서버 상태 확인: `curl -s https://damso.jibang.site/actuator/health` → `{"status":"UP"}`
2. 계약 버전 확인: `gh api repos/damsoWE/damso_server/compare/<앱 사본 태그>...main --jq .ahead_by` → `0` (아니면 새 태그 요청, research R1·R13)
3. 실행 설정: `cp env/example.json env/prod.json` ([contracts/run-config.md](./contracts/run-config.md))
4. 슈퍼 관리자 계정을 배포 담당자에게서 받는다(저장소 밖, research R8)
5. 기기 2대 준비: Android 에뮬레이터 2개 또는 에뮬레이터 + 실기기. 기기 A = 관리자→교사, 기기 B = 학부모
6. 실행: `flutter run --dart-define-from-file=env/prod.json`

테스트 데이터에는 가상의 이름·문장만 쓴다. 기록에는 계정·본문·코드 값을 쓰지 않는다.

## Q2 관리자 운영 (US4) — 다른 시나리오의 데이터를 만든다

| ID | 동작 | 기대 결과 |
|---|---|---|
| Q2-1 | 관리자 로그인 → 학급 생성 → 학생 1명 등록 → 교사 초대 코드·학부모 초대 코드 발급 | 학급 상세에 학생이 보이고 코드가 화면에 표시된다 |
| Q2-2 | 기기 A: 교사 코드로 교사 가입(이메일 인증 포함) | 교사 홈에 담당 학급이 보인다 |
| Q2-3 | 학부모 코드 재발급 → 이전 코드로 가입 시도 | 서버 거부 문구가 보이고 가입이 진행되지 않는다 |
| Q2-4 | 기기 B: 새 학부모 코드로 학부모 가입 | 학부모 홈에 자녀가 보인다 |

## Q1 로그인 유지 (US1)

| ID | 동작 | 기대 결과 |
|---|---|---|
| Q1-1 | 기기 B 로그아웃 후 학부모 로그인 | 학부모 홈 |
| Q1-2 | 앱 완전 종료 → 다시 실행 | 로그인 화면 없이 홈 |
| Q1-3 | 접근 토큰 만료 시간이 지난 뒤 목록 새로 고침 | 로그인 화면 없이 목록이 보인다 |
| Q1-4 | 틀린 비밀번호로 로그인 | 서버 문구만 보인다 |
| Q1-5 | 다른 기기에서 같은 계정 로그아웃/탈퇴 후 이 기기에서 조작 | 로그인 화면으로 이동 |
| Q1-6 | 로그아웃 | 로그인 화면 |
| Q1-7 | 비밀번호 재설정(메일 코드) | 새 비밀번호로 로그인 성공 |
| Q1-8 | (마지막에) 테스트용 학부모 계정 탈퇴 | 시작 화면으로 이동, 같은 계정 로그인 불가 |

Q1-3의 만료 시간은 서버 설정이다. 너무 길면 "차단됨(만료 시간 미도래)"으로 적고 인터셉터 자동 테스트(`test/core/auth_interceptor_test.dart`)로 갈음한다.

## Q3 문의 전달 (US2)

| ID | 동작 | 기대 결과 |
|---|---|---|
| Q3-1 | 기기 B: 일반 문의 작성 → 기기 A: 목록 새로 고침 | 1회 새로 고침 안에 문의가 보인다(SC-002) |
| Q3-2 | 기기 B: 긴급 표현이 든 문의 → 기기 A: 목록 | 긴급 표시, 상세에서 원문이 보인다 |
| Q3-3 | 기기 B: 문의 상세 | 서버가 정한 현재 단계와 안내가 보인다 |
| Q3-4 | 1분 안에 일반 문의 2건 연속 | 서버 제한 문구가 보인다 |
| Q3-5 | 다른 학부모 계정으로 Q3-1 문의 상세 경로 접근(딥링크 등) | 내용 없이 서버 거부 문구 |

## Q4 정리 결과 (US3)

| ID | 동작 | 기대 결과 |
|---|---|---|
| Q4-1 | 기기 A: Q3-1 문의 상세(정리 중이면 "다시 확인") | 정리 완료 시 번역본(사실관계·요청사항·정서강도) |
| Q4-2 | 정리 중 상태에서 당겨서 새로 고침 | 완료되면 번역본으로 바뀐다 |
| Q4-3 | "원문 확인 필요" 문의가 생기면 다시 정리하기 → 다시 시도 | 1회만 가능, 두 번째는 서버 문구·버튼 없음 |
| Q4-4 | 원문 열람 | 원문과 열람 기록 안내 |

Q4-3은 서버의 정리 실패가 나와야 확인된다. 일부러 만들 방법이 없으면 "차단됨"으로 적고 mock 시나리오 테스트로 갈음한다.

## Q5 네트워크·오류 (US5)

| ID | 동작 | 기대 결과 |
|---|---|---|
| Q5-1 | 비행기 모드 → 목록 열기 | 15초 안에 연결 안내 + 다시 시도(SC-004) |
| Q5-2 | 비행기 모드 해제 → 다시 시도 | 목록이 보인다 |
| Q5-3 | 가입 양식에 서버가 거부할 값(형식은 맞지만 중복 이메일 등) | 입력란 아래 또는 화면에 서버 문구 |
| Q5-4 | 모든 시나리오 중 화면 문구 점검 | 예외 내용·내부 코드가 섞인 문구 0건(SC-005) |

## Q6 실행 설정 (US6, FR-014)

| ID | 동작 | 기대 결과 |
|---|---|---|
| Q6-1 | `flutter run --dart-define=USE_MOCK=true` | 서버 없이 로그인 화면, mock 시나리오 동작 |
| Q6-2 | `secrets/firebase.json` 없이 배포 서버로 교사 로그인 → 교사 홈·알림 설정 화면 | 알림 관련 오류 표시 없음 |
| Q6-3 | `flutter build apk --release --obfuscate --split-debug-info=build/debug-info --dart-define-from-file=env/prod.json` 후 설치(`adb install -r build/app/outputs/flutter-apk/app-release.apk`, INTERNET 권한 추가 후) | 로그인 성공 |
