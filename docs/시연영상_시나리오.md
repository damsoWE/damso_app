## 0. 한눈에 보기

- **영상 길이(편집 후)**: 필수 씬만 약 **11분 45초** · 권장·선택 씬 포함 약 **15분 30초**. AI 정리·알림을 기다리는 시간은 편집에서 잘라 낸다. 촬영 자체는 대기·재촬영을 넣어 40~60분을 잡는다.
- **기기 2대**: 학부모 폰(`parent105`, 3학년 1반 5번 권하윤 보호자) · 교사 폰(`teacher1`, 3학년 1반 담임 김지은). 관리자 씬은 세 번째 기기에서 찍는 것을 권장한다.
- **편집 권장 구도**: 화면 분할(왼쪽 학부모 폰, 오른쪽 교사 폰). 알림이 오는 순간은 두 화면을 같이 보여 준다.
- **이야기 흐름**: 학부모가 아이 걱정을 보낸다 → 교사는 AI가 감정을 덜어 정리한 "번역본"으로 받는다 → 원문은 언제든 볼 수 있지만 열람은 기록된다 → 교사가 직접 답한다 → 학부모는 알림을 받고 같은 문의에서 이어서 묻는다 → 아이 안전 문제는 AI를 거치지 않고 즉시 전달된다.

## 1. 준비물·사전 점검 체크리스트

### 1-1. 기기·빌드

- [ ] 릴리스 APK를 `scripts/build-release.sh apk`로 만든다(난독화 + `env/prod.json` + `secrets/firebase.json` 주입). `secrets/firebase.json` 없이 빌드하면 앱은 동작하지만 **기기 알림이 꺼진 채** 실행된다.
- [ ] 촬영할 APK가 지금 작업 트리(커밋 전 화면 변경 포함)로 빌드됐는지 확인 **[확인 필요]**.
- [ ] Android 실기기 2대, Google Play 서비스가 있어야 알림(FCM)이 온다. 에뮬레이터를 쓰면 Play Store가 들어간 이미지로 한다.
- [ ] Android 13 이상이면 홈에 처음 들어갈 때 알림 권한 창이 뜬다. 12 이하는 창 없이 허용된다.
- [ ] 기기 시간대를 **서울(GMT+9)**로 맞춘다. 화면 시각은 기기 시간대로 표시된다(spec 005 검증 때 에뮬레이터가 GMT로 표시됨).
- [ ] 두 기기 모두 안정적인 Wi-Fi에 연결한다.
- [ ] 절전 모드를 끄고 화면 자동 꺼짐 시간을 길게 둔다. 일반 문의·답변 알림은 서버가 10초 간격으로 모아 보내므로 **수 초~20초 늦는 것은 정상**이다. 긴급 알림은 바로 간다.
- [ ] 메신저 등 다른 앱 알림을 끈다(개인 알림이 녹화되지 않게). 방해 금지 모드는 켜지 않는다.
- [ ] 화면 녹화 방법을 정한다(기기 내장 화면 녹화 또는 PC 미러링). 개발자 옵션의 "탭한 항목 표시"를 켜 두면 조작이 잘 보인다.
- [ ] §4 예문을 각 기기 메모 앱에 미리 넣어 두고 붙여넣기로 입력한다(오타 방지·시간 절약).
- [ ] 키보드의 "키 누를 때 팝업"을 끈다(비밀번호 입력이 녹화에 비치지 않게).

### 1-3. 서버에 저장된 설정 값 확인 (촬영 30분 전)

- [ ] **teacher1** → 하단 "마이페이지" → "응답 가능 시간 · 알림"(F3-8)
  - 요일이 하나도 선택돼 있지 않으면 "요일을 고르지 않으면 언제든 응답 가능으로 봐요."가 보인다 → 그대로 두면 된다.
  - 요일·시간이 설정돼 있으면 촬영 시각이 그 안에 들어가는지 본다. 밖이면 일반 문의 접수 화면이 "선생님 응답 가능 시간에 전달됩니다."(F2-5a)로 바뀌고, 교사 일반 알림이 다음 응답 가능 시간으로 미뤄진다.
  - "일반 문의 알림" 스위치가 켜져 있는지 본다.
- [ ] **parent105** → 하단 "마이페이지" → "알림 설정"(F2-8) → "답변 도착 알림"이 켜져 있는지 본다.
- [ ] 두 화면에 "기기 알림이 꺼져 있습니다. 기기 설정에서 담소 알림을 켜 주세요."가 보이면 기기 설정에서 담소 알림을 켠다.

### 1-4. 촬영 전에 미리 만들어 둘 데이터

1. **예문 C(감정이 센 문의) 사전 등록** — `parent103`(권승우 보호자)으로 촬영 **최소 10분 전**에 보낸다.
   - 교사 폰에 "새 문의가 도착했습니다"가 오는지 보면 교사 알림 점검도 같이 된다.
   - 학부모 폰에서 보냈다면 마이페이지 "로그아웃" 후 `parent105`로 로그인해 둔다. 알림 권한 창 장면(씬 3)을 찍을 계획이면 세 번째 기기에서 보낸다.
2. **(선택) 학부모 알림 점검** — 기존 테스트 문의 "숙제량 과다 문의"에 교사가 짧게 답변해 학부모 폰에 "답변이 도착했습니다"가 오는지 확인한다. 이 답변도 영구히 남는다는 점을 감안한다.
3. **기존 데이터 확인(열어 보기만)** — 교사 목록의 권승우 "원문 확인 필요" 건을 열어 "다시 정리하기 · 1회 남음" 버튼이 있는지만 본다. **누르지 않는다**(문의당 1회, 되돌릴 수 없음). 상세 화면을 여는 것만으로는 원문 열람 기록이 남지 않는다("원문 보기"를 눌러야 남는다).
4. 기존 3-1 테스트 문의(권하윤 "학교생활과 친구관계 걱정"·"숙제량 과다 문의", 권승우 "원문 확인 필요")는 지우지 않고 목록을 채우는 보조 자료로 쓴다. 시연의 기본 흐름은 **새 문의를 만들어 보여 주는 것**이다.

### 1-6. 리허설 원칙

- 배포 서버는 운영 DB다. 리허설로 보낸 문의·답변도 **지울 수 없다**. 버튼 위치·화면 흐름 리허설은 mock 디버그 실행(`flutter run --dart-define=USE_MOCK=true`)으로 하고, 배포 서버에서는 본 촬영만 한다.
- 긴급 문의는 리허설하지 않는다(실제 교사 기기에 긴급 알림이 간다).

## 4. 시연용 예문

### 4-0. 예문을 쓰거나 고칠 때 지킬 것

서버는 AI보다 먼저 **정해 둔 표현 목록**으로 긴급을 판정한다(백엔드 `src/main/resources/urgent/expressions.txt`, 띄어쓰기를 지우고 "포함되는지"만 본다). 일반 문의·재문의 예문에 아래 표현이 들어가면 **긴급으로 접수돼 실제 긴급 알림이 간다.** 예문을 고칠 때 특히 조심한다.

- 자해·자살: 자해, 자살, 죽고 싶, 죽어버리, 죽을래, 극단적(인) 선택, 목숨을 끊, 스스로 목숨, 사라지고 싶, 손목을 긋/그, 뛰어내리
- 학대·폭행: 학대, 폭행, 폭력, 때렸, 때려서, 맞고 왔, 맞았다고, 맞았대, 멍이, 멍든, 상처가 났, 회초리, 굶기
- 성적 피해: 성추행, 성폭행, 성폭력, 성희롱, 몸을 만, 신체 접촉
- 실종·가출: 실종, 가출, 집에 안 들어, **연락이 안 돼**, 연락이 되지 않, 행방, 납치
- 위협·흉기: 협박, 위협, 칼을, 흉기, 죽이겠, 죽여버리
- 괴롭힘: 학교폭력, **따돌림, 왕따, 괴롭힘, 괴롭히**

그 밖에:

- 이름 가명화는 같은 반 명단(학생·보호자·교사 이름, 세 글자 이름은 끝 두 글자도)과 학급·학교 표기만 가린다. 다른 반 친구 이름은 가려지지 않으므로 예문에는 같은 반 학생 이름만 쓴다.
- 전화번호·주소를 쓰면 정리본에서는 빠지지만 원문에는 영구히 남는다. 예문에는 넣지 않는다.
- 실제 욕설은 원문 열람 화면(F3-6)에 그대로 보이고 영구히 남는다. 영상용으로는 비하 표현 수준(예문 C)을 권장한다.
- 본문은 2,000자까지.

## 5. 주의사항

- **보낸 것은 지울 수 없다.** 문의·재문의·답변·원문 열람 기록·답변 점검 요청 기록·초대코드 발행 기록은 운영 DB에 영구히 남는다(수정·삭제 API 없음, 원칙 III). 필요한 만큼만 보내고, 다시 찍을 때는 이미 만든 문의를 다시 열어 보여 준다. 3-1 목록이 너무 지저분해지면 예비 학급(3-3·3-4)으로 옮긴다.
- **일반 문의 1분 제한**: 학부모 계정마다 일반 문의(재문의 포함) 60초에 1건. 걸리면 "잠시 후 다시 시도해 주세요." + 남은 초가 보이고 쓴 내용은 남는다. 긴급 문의는 제한을 받지 않는다.
- **원문 열람은 감사 기록이 남는다.** F3-6 "원문 보기"를 누를 때마다, 그리고 긴급 문의 상세(F3-5)는 원문이 바로 보이므로 열 때마다 기록된다. 리허설로 여러 번 열면 기록도 그만큼 쌓인다.
- **번역본을 처음 열면 "교사 확인" 단계가 기록된다.** 되돌릴 수 없다. 씬 6 전에는 새 문의를 열지 않는다.
- **"다시 정리하기"는 문의당 1회**이며 되돌릴 수 없다. 권승우 건에서 누르지 않는다.
- **긴급 문의**는 실제 교사 기기에 즉시 알림이 가고, 교사가 1시간 안에 F3-5를 열지 않으면 다시 알림이 간다. 촬영 뒤 교사가 반드시 F3-5를 열어 둔다. teacher1이 다른 기기에도 로그인돼 있으면 그 기기에도 알림이 갈 수 있다 **[확인 필요]**.
- **알림이 오려면**: Google Play 서비스가 있는 기기 + Firebase 값을 넣어 만든 릴리스 APK + 기기 알림 권한 허용 + 그 역할로 로그인된 상태. 로그아웃하면 그 기기의 알림 등록이 풀린다. 관리자 계정은 알림을 받지 않는다. 교사 기기에 학부모용 알림이 오거나 그 반대면 무시된다.
- **알림 지연**: AI 정리 약 5초, 일반·답변 알림은 서버가 10초 간격으로 보내므로 최대 20초 안팎, 긴급 알림은 바로 간다.
- **앱 데이터 초기화·재설치**를 하면 로그인이 풀려 다시 로그인해야 한다(알림 기기 등록은 로그인 때 다시 된다). 학부모 폰은 권한 창 장면이 필요할 때만 재설치하고, 교사 폰은 초기화하지 않는다.
- **화면에 나오면 안 되는 것**: `계정_정보_담소.pdf`, 비밀번호 입력 키 팝업. **초대코드 값**은 만료 전까지 실제로 가입에 쓸 수 있으므로 편집에서 가린다. 영상을 공개한다면 촬영 뒤 그 학생 코드를 "재발행"해 녹화된 코드를 무효로 만든다(새 코드는 녹화하지 않는다). 마이페이지에는 계정 이메일이 보인다(시연용 `example.com` 계정이라 괜찮다).
- **3학년 2반**은 시연 데이터가 아니다. 관리자 목록·문의 현황에 보이지만 누르지 않는다.
- **112·109 전화 버튼**을 누르면 기기 전화 앱이 번호가 입력된 채 열린다. 통화 버튼은 절대 누르지 않는다. 전화 기능이 없는 기기(태블릿 등)에서는 버튼이 비활성으로 보인다.
- **mock 보조 컷(10-b)**은 디버그 실행에서만 된다. 배포 서버 화면이 아니므로 자막으로 밝힌다.
- 이 앱에는 학부모·교사 알림 목록(🔔, F2-6·F3-11)과 문의 닫기 기능이 없다. 시나리오에 넣지 않는다.

## 7. 확인 필요 항목

코드·문서로 확인하지 못해 촬영 전(또는 촬영 중)에 직접 봐야 하는 것.

1. **배포 서버의 답변 점검 결과** — 백엔드 main(`ed456cf`)은 항상 "점검 실패"를 돌려주는 임시 구현이라 F4-2f가 나올 것으로 예상한다. 제안 카드·"바꾸기"(F4-2c·F4-2c-1)가 배포 서버에서 나오는지 확인이 필요하다. 안 나오면 보조 컷 10-b(mock)로 대신한다.
2. **긴급 위기 종류 분류 결과** — 예문 D가 분류 뒤 "109만"으로 바뀌는지(AI 분류라 다를 수 있음).
3. **감정이 센 문의의 정리 결과** — 정서강도·감정 라벨, 사실관계 끝 "교사를 향한 폭언이 있었다." 문장이 붙는지(AI 판정).
4. 자동 정리 **제목·요청사항 문구**(서버 값).
5. teacher1의 **공개 프로필 표시 이름·소개 문구**(문의 작성 "받는 분", 스레드 "… 선생님 · 직접 전송", 학부모 홈 담임 카드).
6. 권승우 "원문 확인 필요" 건에 **"다시 정리하기 · 1회 남음"이 남아 있는지**.
7. 기존 3-1 테스트 문의의 **답변 여부**("답변 대기 N · 답변 완료 N" 숫자).
8. teacher1의 **응답 가능 시간·일반 문의 알림** 현재 값, parent105의 **답변 도착 알림** 현재 값.
9. parent105에 **연결된 자녀 수**(자녀 선택 화면에 무엇이 보이는지).
10. 예비 학급(3-3·3-4)에서 **학부모가 연결된 번호**.
11. 촬영 APK가 **현재 작업 트리(커밋 전 화면 변경 포함)**로 빌드됐는지.
12. 같은 교사 계정이 **다른 기기에도 로그인돼 있을 때** 그 기기에도 알림이 가는지.
13. 앱 **데이터 삭제만으로 알림 권한이 초기화되는지**(기기마다 다를 수 있어 재설치를 권장).
14. **iOS 알림** 동작 — 이 시나리오는 Android 릴리스 APK 기준이다.
